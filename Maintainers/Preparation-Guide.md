# 새 문서 프로젝트를 위한 준비 (Preparation Guide)

> 현재 저장소는 나중에 별도 문서 프로젝트를 집필할 때 재구성할 주제, 설명, 예제, 출처를 보관한다.

## 현재 목표

2026-09-11 기준, 현재 작업의 목표는 재작성에 필요한 재료를 확보하는 것이다. 사람 검토와 `Complete` 승격은 이 준비 단계의 작업이나 완료 조건에 포함하지 않는다. `Reviewed-by: -`를 유지하며, 출처 확인과 코드 실행 결과는 아래 재작성 메모에 별도로 남긴다.

기존 `Status`, `Depth`, 로드맵은 자료를 찾는 데 활용한다. 이 값만으로 새 프로젝트에 그대로 옮길 수 있다고 판단하지 않는다. 직접 출처, 구체 예제, 보충할 질문을 함께 확인한다.

## 전체 자료 찾기

[Preparation-Inventory.md](Preparation-Inventory.md)는 모든 학습 주제에서 직접 출처, 구현 후보 블록, 재작성 메모를 찾아 모은 자동 목록이다. 다음 순서로 보강 대상을 고른다.

1. 새 프로젝트에서 사용할 주제 또는 [Coverage-Matrix.md](Coverage-Matrix.md)의 공통 기초 경로를 고른다.
2. 출처가 없는 문서에는 핵심 주장과 연결되는 원문을 추가한다.
3. 설명 골격만 있는 문서에는 입력·과정·결과가 있는 예제를 추가한다.
4. 재사용할 부분과 추가 조사할 질문을 문서 끝에 기록한다.

목록의 수치는 존재 여부다. 링크가 있다는 것만으로 출처가 주장을 뒷받침하거나, 코드 블록이 있다는 것만으로 코드가 실행되거나, 메모가 있다는 것만으로 재작성 준비가 끝났다고 보지 않는다. 메모가 없는 문서는 조사할 내용이 없는 것이 아니라 아직 기록하지 않은 것이다.

## 출처를 남기는 방법

각 주제의 `## 참조 (References)`에 원 논문, 공식 문서, 저자·대학 자료의 직접 링크를 넣고 어떤 주장에 사용하는지 적는다. 중앙 [Reference/](../Reference/) 목록은 분야 탐색에 함께 사용한다.

- 논문은 제목·저자·연도와 원문 링크, 필요한 절 또는 정리 번호를 남긴다.
- 책은 판본과 장·절을 적고 저자 또는 출판사 페이지로 연결한다.
- 도구 문서는 해당 기능의 공식 페이지와 사용 버전을 적는다.
- 출처를 열어 확인했다면 날짜와 확인 범위를 메모한다. 원문을 열지 못했다면 미확인으로 기록한다.
- 예제에 사용하는 가상 수치는 가정으로 표시한다. 측정하지 않은 결과를 벤치마크나 실측값으로 쓰지 않는다.

출처 본문을 옮겨 적지 않고, 직접 쓴 설명과 필요한 링크를 보관한다. 출처가 삭제되어도 무엇을 확인하려 했는지 제목과 지원하는 주장이 남아야 한다.

## 예제를 남기는 방법

재사용할 예제에는 입력, 가정, 처리 과정, 기대 결과가 있어야 한다. 계산·증명 예제는 중간 단계와 경계 조건을, 코드 예제는 실행 환경과 명령 또는 실행 방법을 기록한다.

실행 가능한 예제와 연결 구조를 보여 주는 의사코드를 본문에서 구분한다. 외부 모델·데이터·서비스가 필요한 부분은 의존성을 적고, 실제 실행한 범위만 확인 상태에 남긴다. 최소 예제를 통과했다고 성능·보안·분산 장애까지 검증했다고 기록하지 않는다.

## 재작성 메모

새로 작성하거나 보강하는 주제는 참조 섹션 뒤에 다음 제목과 세 항목을 쓴다. 기존 모든 문서에 같은 문구를 일괄 삽입하지 않고, 실제 확인한 내용을 기록한다.

```text
## 재작성 메모 (Rewrite Notes)

- 재사용할 재료: 새 문서에 가져갈 설명·수식·예제와 해당 절.
- 보충할 내용: 아직 없는 증명, 실패 사례, 실습, 출처 또는 추가 조사할 질문.
- 확인 상태: 확인 날짜, 원문에서 확인한 주장, 실행 환경·방법·결과, 실행하지 않은 범위.
```

예를 들어 “예제 보강 필요” 대신 “중복 원소가 있는 입력에서 lower bound와 임의 일치 검색 결과를 비교하는 실행 추적 추가”처럼 다음 행동을 적는다. 새로운 원고의 문체나 장 구성이 아직 정해지지 않아도 이 기록은 재사용할 수 있다.

## 목록 갱신과 이관

저장소 루트에서 실행한다. Markdown 목록은 직접 수정하지 않는다.

```powershell
python Maintainers/Scripts/build_preparation_inventory.py --write
python Maintainers/Scripts/build_preparation_inventory.py --check
python Maintainers/Scripts/build_preparation_inventory.py --format json
```

JSON은 새 프로젝트에서 분류·선별할 때 사용하는 기계 판독용 목록이다. 실제 본문은 각 파일에 남아 있다. JSON을 저장해 사용한다면 파일 내용이나 줄 위치가 바뀔 때 다시 내보낸다. Markdown 목록의 `--check`는 표시되는 출처 수·코드 수·메모 유무 등의 변화를 검사하며, 본문의 모든 변경을 검사하지 않는다.

이관할 때는 원래 문서 경로와 Git 커밋, 직접 출처와 확인 메모를 함께 보관하고, 새 장에 맞춰 선수지식과 상대 링크를 다시 연결한다. 본문·코드의 재사용 조건은 [LICENSE](../LICENSE)에 남아 있다.
