## 금지 콘텐츠

다음 내용은 저장소에 추가하지 않는다.

| 유형 | 예 |
|---|---|
| 저작권 있는 본문 복사 | 책, 강의 노트, 블로그, 논문, 유료 강의 자막을 길게 복사한 내용 |
| 문제/해설 무단 복제 | 교재 연습문제, 온라인 저지 유료 문제, 시험 문제, 답안지를 그대로 옮긴 내용 |
| 불법 공유 링크 | 불법 PDF, 크랙, 토렌트, paywall 우회 링크 |
| 라이선스 불명 코드 | 출처와 라이선스가 불분명한 외부 코드 조각 |
| 라이선스 충돌 코드 | 저장소 사용 조건과 맞지 않는 GPL 등 강한 copyleft 코드의 무단 복사 |
| 상표/로고/이미지 무단 사용 | 공식 허가 없는 로고, 책 표지, 강의 슬라이드 이미지, 저작권 있는 다이어그램 |
| 개인정보와 비밀정보 | 실명/전화번호/이메일/주소, API 키, 토큰, 비밀번호, 내부 URL |
| 불법 행위 조장 | 실제 대상 공격, 우회, 침해, 악성코드 배포를 돕는 절차 중심 설명 |

보안, 암호학, 네트워크, 리버스 엔지니어링 같은 주제는 교육적 설명과 방어적 맥락으로 제한한다. 실제 서비스나 타인의 시스템을 침해하는 단계별 지침은 작성하지 않는다.

## 허용되는 방식

| 상황 | 허용 방식 |
|---|---|
| 책/강의 내용을 참고 | 직접 이해한 뒤 새 문장으로 요약하고, [Reference/](../Reference/)나 참조 섹션에 출처를 남긴다 |
| 짧은 인용이 필요한 경우 | 필요한 최소 문장만 인용하고, 따옴표와 출처를 명확히 남긴다 |
| 논문 설명 | 초록/본문을 길게 복사하지 말고 핵심 아이디어, 전제, 한계, 응용을 직접 요약한다 |
| 코드 예제 | 직접 작성한 최소 예제를 사용한다 |
| 외부 코드가 꼭 필요한 경우 | 라이선스를 확인하고, 허용되는 범위와 출처를 명시한다 |
| 다이어그램 | 직접 만든 ASCII, Mermaid, 표, 자체 설명을 우선한다 |
| 이미지 | 공개 라이선스가 명확한 자료만 쓰고 출처/라이선스를 남긴다. 직접 만든 ASCII/Mermaid로 대체 가능하면 그쪽을 우선하고, 파일이 필요하면 `assets/<Section>/`에 둔다 |

짧은 인용도 문서의 핵심 내용을 대체할 만큼 많이 쓰면 안 된다. 이 저장소의 학습 가치는 원문 복사가 아니라 독립적인 설명과 연결 구조에서 나온다.

## 참조 링크 규칙

- 공식 문서, 출판사 페이지, 저자 페이지, 학회/저널, arXiv, 대학 공개 강의처럼 안정적인 출처를 우선한다.
- 불법 업로드 PDF, 파일 공유 사이트, 크랙 사이트, paywall 우회 안내는 링크하지 않는다.
- 강의나 책의 핵심 내용은 링크로 안내하고, 저장소 본문에 대량 전재하지 않는다.
- 외부 자료가 삭제되거나 유료화되어도 본문이 독립적으로 이해될 수 있게 작성한다.

## 작성 전 체크리스트

새 문서나 큰 수정은 다음 질문을 통과해야 한다.

- 이 설명은 내가 직접 작성한 문장인가?
- 외부 자료의 문장, 표, 그림, 코드가 그대로 들어오지 않았는가?
- 필요한 출처 링크를 참조 섹션에 남겼는가?
- 유료/비공개/불법 공유 자료에 의존하지 않았는가?
- 예제 코드의 라이선스와 출처가 명확한가?
- 실명, 토큰, 내부 주소, 비밀번호 같은 민감 정보가 없는가?
- 보안 관련 내용이 실제 침해 절차가 아니라 방어적/교육적 설명인가?

하나라도 확신이 없으면 `Draft`로 올리기 전에 관리자 검토를 받는다.

## 문제 발견 시 처리

법적/저작권 리스크가 있는 내용을 발견하면 다음 순서로 처리한다.

1. 문제가 되는 문장, 코드, 이미지, 링크를 즉시 제거하거나 비공개 검토 대상으로 표시한다.
2. 원문 출처와 라이선스를 확인한다.
3. 허용 가능하면 직접 작성한 요약으로 대체하고 출처를 남긴다.
4. 허용 여부가 불확실하면 해당 내용을 저장소에 유지하지 않는다.

저장소 유지보수자는 저작권, 라이선스, 개인정보, 보안 리스크가 의심되는 변경을 사전 통보 없이 거절하거나 되돌릴 수 있다.
