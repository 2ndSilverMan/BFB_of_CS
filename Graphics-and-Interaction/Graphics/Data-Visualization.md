## 개념 (Concept)

데이터 시각화는 데이터 속 속성과 관계를 위치·길이·색 같은 시각적 표현에 대응시켜 질문에 답하도록 만드는 설계다. 예쁜 그림을 만드는 것과 다른 목표이며, 계산이 맞아도 분모·축·집계가 질문과 다르면 오해를 만든다. 여기서는 과업 정의, 인코딩 선택, 집계와 불확실성의 사례를 다룬다.

## 직관 (Intuition)

“오류가 많은 서비스”는 오류 건수가 많은 서비스인지, 요청 대비 오류 비율이 높은 서비스인지 애매하다. 같은 표에서 두 질문의 답이 다를 수 있다. 차트를 고르기 전에 무엇을 비교하려는지와 분석 단위를 정해야 한다.

## 이론 (Theory)

범주형 변수의 이름에는 임의 순서가 있을 수 있지만 수치형 변수에는 차이·비율 해석이 있다. 시간 추세는 시점 간 순서, 분포는 빈도와 변동, 관계는 쌍의 대응이 중요하다. 위치·길이·색의 채널을 목적에 맞게 고르고 단위·범위·결측 처리·분모를 드러낸다.

[Munzner의 nested model](https://www.cs.ubc.ca/labs/imager/tr/2009/NestedModel/)은 도메인 문제, 데이터/과업 추상화, 시각 표현/상호작용, 알고리즘의 서로 다른 설계·검증 수준을 구분한다. 빠르게 그려지는 차트라도 사용자의 질문을 잘못 추상화했다면 실패할 수 있다.

평균은 분모를 숨기기 쉽다. 요청이 100개인 날 10% 실패하고 900개인 날 1% 실패했다면 일별 비율의 단순 평균 5.5%는 전체 요청의 실패율이 아니다. 전체는 (10+9)/(100+900)=1.9%다. 어느 값이 옳은지는 “무작위 하루”와 “무작위 요청” 중 무엇이 대상인지에 달려 있다.

## 구현 (Implementation)

아래는 가상 데이터의 집계 확인 코드다. 차트 라이브러리 없이도 데이터 정의를 먼저 검산한다.

```python
from math import isclose

daily = [{"requests": 100, "errors": 10},
         {"requests": 900, "errors": 9}]
rates = [row["errors"] / row["requests"] for row in daily]
day_mean = sum(rates) / len(rates)
request_rate = sum(r["errors"] for r in daily) / sum(r["requests"] for r in daily)
assert isclose(day_mean, 0.055)
assert isclose(request_rate, 0.019)
assert not isclose(day_mean, request_rate)
```

이 자료의 두 가지 차트 설계 명세를 비교한다. 실제 사용자 평가를 한 결과가 아니라 설명용 설계안이다.

| 설계 | 전달하려는 질문 | 표시할 것 | 예상 한계 |
|---|---|---|---|
| 일별 비율 막대 | 어느 날 오류율이 높은가 | 0 기준 비율 축, 날짜, 분모 100/900 | 전체 요청의 경험은 직접 보여주지 못함 |
| 전체 실패/성공 막대 | 전체 요청 중 얼마나 실패했나 | 실패 19, 성공 981, 총 1,000 | 날짜별 차이는 사라짐 |

막대 길이로 비율을 비교하는데 y축을 9~10%만 보여주면 작은 차이를 크게 보이게 할 수 있다. 모든 차트가 항상 0에서 시작해야 한다는 뜻은 아니다. 선 그래프의 작은 변동이나 로그 축이 목적에 적합할 수도 있으나 축과 해석을 명시해야 한다. 색만으로 상태를 구별하지 말고 레이블·기호·표를 함께 제공한다.

## 복잡도 (Complexity)

N개 기록의 단순 집계는 O(N)이고 화면 표식 수가 커지면 겹침과 인지 부담이 증가한다. 다운샘플링·binning은 비용을 줄이지만 극단값이나 짧은 사건을 숨길 수 있다. 불확실성 구간은 어떤 추정량·방법·가정을 사용했는지 명시해야 하며, 작은 표본의 불안정성을 장식으로 처리하지 않는다.

## 응용 (Applications)

운영 대시보드, 실험 결과, 공공 통계, 성능 보고서에 적용한다. 보고서의 표와 그래프는 같은 모집단·기간·필터를 사용했는지도 확인한다.

## 흔한 오해 (Common Misunderstandings)

- 정렬·색만 바꾸면 중립적이다: 강조·순서도 해석에 영향을 준다.
- 결측치는 0으로 넣으면 된다: 관측하지 않음과 실제 0은 다르다.
- 오차 막대가 겹치면 차이가 없다: 구간 종류·추정량·비교 검정을 확인해야 한다.

## TMI

- 비율의 평균과 합계의 비율은 같은 연산이 아니다.
- 표본 수를 표기하는 작은 주석이 화려한 상호작용보다 해석에 중요할 수 있다.

## 연습 / 확인 문제 (Exercises)

1. 200개 중 20개 실패, 800개 중 8개 실패의 전체 실패율은? **답:** 28/1000=2.8%. 두 날 비율의 평균은 5.5%다.
2. 요청 0개인 날짜의 비율을 0으로 표시해도 되는가? **답:** 정의되지 않은 비율이다. 요청 없음으로 표시하고 집계 정책을 설명한다.
3. 위 두 설계 중 하나를 고르고 개선하라. **판단 기준:** 질문·단위·분모·축·접근성·집계 한계가 모두 명시되어야 한다.
