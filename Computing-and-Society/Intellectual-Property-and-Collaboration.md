## 개념 (Concept)

공개 협업에서는 자료를 읽을 수 있다는 사실, 복제·수정·배포할 권한, 기여를 인정할 의무를 구분해야 한다. 저작권·특허·상표·계약·개인정보 권리는 서로 다른 문제다. 이 문서는 공개 자료를 재사용할 때 확인할 절차를 설명하며 구체 분쟁의 법률 판단을 대신하지 않는다.

## 직관 (Intuition)

인터넷에서 찾은 그림에 출처를 적는 것은 정직한 설명이지만 그 자체로 복제 허락이 생기는 것은 아니다. 반대로 재사용 허락이 있어도 누가 만들었는지와 무엇을 바꿨는지 기록하지 않으면 조건을 놓치거나 원저자의 기여를 지울 수 있다.

## 이론 (Theory)

라이선스는 허용되는 이용과 조건을 확인하는 출발점이다. 저장소 루트의 라이선스가 외부 이미지·데이터·서브모듈에 모두 동일하게 적용되는지 확인해야 한다. 특정 파일의 원출처와 예외 고지가 우선적으로 중요할 수 있다.

[CC BY 4.0 요약](https://creativecommons.org/licenses/by/4.0/)은 저작자 표시, 라이선스 연결, 변경 표시 등의 조건 아래 공유·수정을 허용한다고 설명한다. 이 요약은 전체 legal code를 대신하지 않는다. [MIT 라이선스 원문](https://spdx.org/licenses/MIT.html)은 허용 범위와 함께 저작권·허가 고지를 사본이나 상당 부분에 포함하는 조건을 둔다. 여기서 서로 다른 라이선스의 결합 가능성이나 특허 문제 전체를 판정하지 않는다.

인용과 표절 방지는 이용 허락과 별도로 필요하다. 아이디어를 바탕으로 새 설명을 쓰더라도 중요한 지적 출처를 표시한다. 코드·데이터를 공동 작성했다면 커밋 수만으로 기여를 판단하지 않고 설계·검증·자료 수집·문서화도 기록한다.

## 구현 (Implementation)

다음은 실제 외부 자산을 가져온 기록이 아닌 가상 이관 판단이다.

| 항목 | 확인된 조건 | 처리 |
|---|---|---|
| 직접 작성한 계산 예제 | 작성 이력 보유 | 저장소의 해당 라이선스 적용 확인 |
| CC BY 4.0 그림 | 원저자·원문·라이선스·변경 내역 확인 가능 | 조건에 맞는 고지를 준비하고 예외 권리 확인 |
| MIT 코드 일부 | 원본 고지와 버전 확인 가능 | 고지 보존, 수정 표시와 기능 검증 |
| 출처 불명 슬라이드 캡처 | 작성자·이용 조건 미확인 | 포함하지 않고 원문 링크 또는 직접 만든 설명으로 대체 |
| 개인정보 포함 데이터 | 코드 라이선스만 확인 | 데이터 권한·개인 영향 별도 확인 전 공개 보류 |

이관 메모에는 다음 필드를 둔다.

- 원제목·작성자·원문 URL·확인 날짜·버전/커밋.
- 실제 재사용한 파일·절·그림·코드 범위.
- 적용 라이선스와 예외 고지의 위치.
- 수정한 내용과 원본 고지를 보존한 위치.
- 재배포 권한 외 아직 확인하지 못한 권리·개인정보 문제.

예를 들어 그림을 다시 그렸더라도 원본의 창작적 표현을 재사용했는지, 단순 사실을 새로 표현했는지는 구체적인 문제다. “재그림이면 무조건 자유”라고 단정하지 않는다. 불확실하면 복제물을 넣지 않고 학습한 내용을 독립적으로 설명하고 원문을 연결한다.

## 복잡도 (Complexity)

의존성과 자산이 N개면 최소한 출처·조건을 N개 단위로 추적해야 한다. 버전 변경·라이선스 예외·재배포 형태가 추가되면 단순 파일 검색만으로 충분하지 않다. 자동 라이선스 스캐너는 증거를 찾는 보조 도구이지 모든 권리를 보증하는 판정기가 아니다.

## 응용 (Applications)

문서 재작성, 오픈소스 기여, 연구 산출물 공개, 강의 자료 제작에 적용한다. 이 저장소의 구체 재사용 조건은 [LICENSE](../LICENSE)와 해당 파일의 추가 고지를 확인한다.

## 흔한 오해 (Common Misunderstandings)

- 출처만 달면 무엇이든 가져와도 된다: 이용 권한과 출처 표시는 다른 문제다.
- 공개 Git 저장소면 모두 오픈소스다: 명시된 허가 조건을 확인해야 한다.
- 코드의 라이선스가 데이터 권한도 해결한다: 별도 권리와 개인정보 조건이 있을 수 있다.

## TMI

- 라이선스의 이름만 기록하기보다 식별자·버전·원문을 함께 남겨야 동명이거나 다른 판본을 혼동하지 않는다.
- “수정 없음”도 유용한 기록이다. 무엇을 원본으로 보존했는지 구분할 수 있다.

## 연습 / 확인 문제 (Exercises)

1. 라이선스 없는 블로그 그림을 출처와 함께 저장소에 넣어도 된다고 단정할 수 있는가? **답:** 아니다. 조건·허락·적용 예외를 확인하지 않았다.
2. 외부 자료의 출처가 사라지면 어떤 기록이 도움이 되는가? **답:** 제목·작성자·버전·재사용 범위·확인한 조건과 고지 위치.
3. 공개 데이터에서 이름만 지우면 배포할 수 있는가? **답:** 재사용 권한과 재식별·개인정보 문제를 각각 확인해야 한다.
