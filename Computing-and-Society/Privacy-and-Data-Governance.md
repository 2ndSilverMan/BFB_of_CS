## 개념 (Concept)

프라이버시는 데이터가 개인에게 어떤 영향을 주는지를 다루며, 데이터 거버넌스는 목적·품질·권한·보관·책임을 관리하는 의사결정 체계다. 암호화로 외부 유출을 막아도 불필요한 추적·부당한 추론·예상 밖 재사용의 위험은 남는다. 여기서는 데이터 흐름과 최소화 설계를 다루고 법률상의 처리 근거·보관 기한을 확정하지 않는다.

## 직관 (Intuition)

“나중에 쓸지 모른다”는 이유로 모든 로그를 저장하면 미래 분석의 선택지는 늘지만 피해·관리 비용도 늘어난다. 데이터는 수집 서버에만 있는 것이 아니라 분석 테이블, 캐시, 백업, 내보낸 파일에도 복제된다. 삭제 버튼 하나가 생애주기 전체의 삭제를 뜻하지 않는다.

## 이론 (Theory)

먼저 목적별 데이터 흐름을 작성한다. 수집 → 저장 → 변환 → 공유 → 보관 종료의 각 단계에 책임자·필드·접근자·보존 조건을 붙인다. [NIST Privacy Framework](https://www.nist.gov/privacy-framework)는 프라이버시 위험을 조직의 위험 관리와 연결하는 자발적 프레임워크다. 법률 준수 인증이나 특정 보관 기한을 자동 제공하는 규칙은 아니다.

데이터 최소화는 필드 수만 줄이는 일이 아니다. 정확도·빈도·보관 기간·결합 가능성도 줄일 수 있다. 정확한 위치 대신 지역 단위, 사용자별 기록 대신 충분히 큰 집계, 영구 식별자 대신 목적별 짧은 수명의 식별자를 검토한다. 가명화는 연결 키와 다른 자료로 재식별 가능성이 남을 수 있으며 완전 익명화를 자동 보장하지 않는다.

접근 권한은 업무 목적에 맞게 부여하고 변경·조회·내보내기를 기록한다. 거버넌스에는 “누가 승인했나”와 “어떤 필드가 어디로 파생됐나”라는 계보도 포함한다.

## 구현 (Implementation)

가상 학습 앱의 목적은 “문제별 오답률을 파악해 설명을 개선”하는 것이다. 실명·정밀 위치·전체 키 입력은 이 목표에 필요하다는 근거가 없다.

| 자료 | 제안한 처리 | 이유와 남는 위험 |
|---|---|---|
| 문제 ID와 정오답 | 일별 집계 | 문항 개선에 직접 필요; 작은 집계의 노출 위험 검토 |
| 계정 ID | 운영 테이블에만 제한 | 학습 기록 기능에는 필요할 수 있지만 집계에 그대로 복사하지 않음 |
| 자유 서술 | 기본 수집 제외 | 민감한 내용을 사용자가 넣을 수 있음 |
| 접속 보안 로그 | 별도 목적·권한·기간 | 분석 편의로 무기한 합치지 않음 |
| 백업 | 복구 시 삭제 요청 재적용 정책 | 서비스 DB 삭제만으로 끝나지 않음 |

정해진 보관 일수는 여기서 법정 기한처럼 만들지 않는다. 목적·계약·적용 규정·위험 평가로 정하고 근거를 남겨야 한다.

설계 확인 시나리오는 다음과 같다.

1. 분석가가 집계 목적에 필요 없는 계정 식별자를 내보내려 하면 거부되는가?
2. 원본 필드가 바뀌면 파생 테이블·대시보드 담당자가 알 수 있는가?
3. 삭제 대상이 백업에서 복구될 때 재노출을 막는 절차가 있는가?
4. 작은 그룹을 필터로 반복 조회하여 개인 결과를 추론할 수 있는가?
5. 새 추천 기능이 기존 수집 목적을 바꾼다면 재평가 책임자는 누구인가?

이 질문의 기대 결과는 특정 제품의 인증이 아니라 결정과 책임이 추적되는 설계 기록이다.

## 복잡도 (Complexity)

위험은 기록 수뿐 아니라 결합 가능성·민감도·영향과 관련된다. 집계 임계값 하나만으로 모든 추론 공격을 막을 수 없다. 차등 프라이버시 같은 정량 기법은 별도 가정·예산·구현 검증이 필요하다. 유용성을 거의 잃지 않는 최소화가 가능한지 먼저 확인하되, 남는 위험을 0이라고 쓰지 않는다.

## 응용 (Applications)

제품 분석, 연구 데이터, 관측 로그, 고객 지원, 데이터 공유에 사용한다. 데이터 품질 책임과 개인에게 미치는 영향은 함께 고려하되 서로 다른 문제로 기록한다.

## 흔한 오해 (Common Misunderstandings)

- 암호화하면 프라이버시가 해결된다: 승인된 내부 사용 자체가 과도할 수 있다.
- 이름만 지우면 익명이다: 준식별자와 외부 자료의 결합을 고려해야 한다.
- 사용자가 삭제를 누르면 백업도 즉시 사라진다: 저장·복구 구조와 정책을 확인해야 한다.

## TMI

- 로그의 request ID도 다른 시스템의 사용자 ID와 연결되면 식별 가능성이 달라진다.
- 오래된 데이터가 정확하지 않게 되는 문제도 잘못된 의사결정과 피해를 만들 수 있다.

## 연습 / 확인 문제 (Exercises)

1. 오답률 분석에 정확한 생년월일이 꼭 필요한가? **예시 답:** 보통 먼저 필요성을 입증해야 한다. 연령대 비교가 목적이어도 더 거친 범주와 결합 위험을 검토한다.
2. 승인된 직원이 목적 밖 조회를 했다면 보안 사고가 아니므로 무시해도 되는가? **답:** 안 된다. 목적·권한·책임 위반과 개인 영향을 조사해야 한다.
3. 위 표에 보관 종료 열을 추가하라. **판단 기준:** 임의의 법정 기한을 쓰지 말고 결정 근거·책임자·파생 자료 처리를 포함한다.
